# 席位用绝对路径写主检出,绕过隔离

## 现象与病根

跑机 .30 run 001:集成分支每小时 18~38 个提交,**master 七小时没动**
(08-14 23:40 → 08-15 06:38 人工清障后一次性落地 184 个),四小时后复发。

堵点是主检出里一个未提交的 `pkg/sql/conn_executor.rs`。**席位用绝对路径写了主检出** ——
隔离靠 cwd,而绝对路径绕开 cwd。写进主检出的内容不在任何节点分支上,`add -A` 够不着它,
于是 `intoTrunk` 那一跳被 git 拒绝,而集成分支照常前进。

| 证据 | 读数 |
|---|---|
| 事件流里落在主检出的写 | `Update(<主检出>/pkg/sql/conn_executor.rs` ×4、`truncate.rs`、`replica_rangefeed.rs`… |
| 对照:落在工作区里的写 | 3483 条 |
| node.md 里指向主检出的绝对路径 | **2566 次**(是提示词自己教的) |
| 跑机上 `/home/esgyn/work/…` 这条**软链**别名 | node.md 里 1170 次 |

观测到的越界全是 Edit/Write 的 `file_path`。另有一次独立事故是 **Bash** 干的
(席位在集成工作区跑 `devenv shell`,devenv 改写了受跟踪的 `devenv.lock`),
所以「只防 Edit/Write 就够」不成立。

---

## 现在的设计

### 一、git 的输出语言锁成 `LC_ALL=C`(`gitSpawnEnv`)

这个仓库到处在拿正则读 git 的原话下判断(`overwriteBlocked`、`stagedBlocked`、
「没有可中止的合并」),而 `spawn` 不给 env 就继承用户 locale。**跑机上 git 说中文** ——
这个仓库自己两处逐字记着「您对下列文件的本地修改将被合并操作覆盖:devenv.lock」。
也就是说事故现场那台机器上,这些英文判据一条都不命中。

`LANGUAGE` 要**删键**不是设空:gettext 里它优先于 `LC_ALL`,而「空串算不算未设置」
各实现不一致。代价是 git 的原话上屏时是英文 —— **能被机器读的那一份必须稳定**,
给人看的解释我们自己用中文写。

实测(`LANG=en_US.utf8 LANGUAGE=zh_CN` 能让 git 说中文,即使没生成 zh_CN.UTF-8):
裸 spawn 下 `overwriteBlocked` 不命中,过 `gitSpawnEnv` 命中。顺带救活了 `stagedBlocked`
和 `merge --abort` 的判据。副作用四个方向都试过没打穿:`core.quotepath` 与 locale 无关、
merge 消息里的非 ASCII 路径从不转义、中文提交信息逐字节正确、Bun 下 `{...process.env}` 不误伤。

### 二、硬闸:写工具的路径不许落在主检出

位置在 `runAgentAdapter` 的 `canUseTool` 包装里,排在 `deps.canUseTool` **之前** ——
bypassPermissions / allowlist 的短路发生在那个实现内部。闭包里有
`req.node`/`role`/`phase`/`cwd`,**归因是免费的**。

拒绝理由里**告诉席位它自己的工作区在哪**:它拿的是提示词里写死的绝对路径,
根本不知道自己有工作区。这是带内纠正 —— 只报告的方案永远做不到。

四个前提,缺一条闸就漏:

- **`override.requireCanUseTool: true`**。没有它,一个自动放行的 PreToolUse 钩子会让
  `resolveHookPermissionDecision` 直接返回,`canUseTool` **一次都不被调用** ——
  闸和登记簿一起消失。运行时实证:不设是 0 次,设了是 1 次。
  副作用要说出口:`/et` 子 agent 里用户的自动放行钩子因此失效。
- **只管写工具**(`Edit`/`Write`/`MultiEdit`/`NotebookEdit` 白名单)。不看工具名的话
  `Read` 一个主检出绝对路径也被拒,而**读一个文件从来不会挡住合并** —— 这一层的全部
  理由是「写进主检出的内容到不了集成分支」,那句话对读不成立。而席位手上就有主检出的
  绝对路径(根方案的「工作目录」是它,方案正文里的路径又被全树复制),拿它去 Read 是常态。
  白名单而不是黑名单:漏进一个写工具只是少拦一次(保守方向),而新增一个读工具不该
  自动获得被拒的资格。
- **工具名要从对象上取**(`toolNameOf`)。`canUseTool` 第一个参数是 `ToolType` **对象**,
  `String(args[0])` 在生产上是 `"[object Object]"` —— 拿它比白名单会让闸整个变成空操作,
  而且编译通过、测试全绿(测试里喂的是字符串)。
- **相对路径要按 `cwd` 解开**。`../../x.ipynb` 一样能爬出工作区。`Edit`/`Write` 侥幸没事
  (`backfillObservableInput` → `expandPath` 在 `canUseTool` 之前已经转成绝对路径),
  而 `NotebookEdit` 是唯一**没有** `backfillObservableInput` 的写工具。

软链走**解被写的那条路径**(`resolveLinks`,注入到 `escapedPathsIn`),
不去枚举「有哪些软链指向仓库」—— 那枚举不完。文件还不存在时(Write 新建)沿着
最近的**已存在祖先**解再接回去。解不开就退回按字面比:**少拦一次可以,崩掉不行**。

### 三、回主干走快进(`intoTrunk` 的前置同步)

真 git 实测:主检出**索引**里有一个无关文件脏时,真三方合并 `exit=2` **整个拒绝**
(而且点名的文件这次合并根本没碰),快进则 `exit=0` 合上、脏文件毫发无损。
跑机上量到过 607 个提交被 3 个不相干的脏文件堵死。

所以先把用户分支合进集成分支,让那一跳变成快进。三条纪律:

- **失败要说**(`onNotice`)。集成工作区索引里只要有一个 staged 文件,前置同步就每一次
  都失败 —— 收益一次都不发生,而返回码此前被整个丢掉。把 intPath 弄成 staged 的
  正是在里面开会的集成验收席位。
- **收拾要复核**,判据是「MERGE_HEAD **或** unmerged 条目」,不是只看 MERGE_HEAD ——
  这个文件自己记着实测「a lost merge race leaves a staged entry with NO MERGE_HEAD」。
  一条 abort 不够就 `reset --hard` + `clean -fd`。
  ⚠ 重手之前**钉不住是常态**:冲突态下 `stash push -u` 和 `stash create` 都失败
  (`needs merge`)。所以抹之前先把名字记下来(`status` 在冲突态下照常工作),
  钉住了报 ref,**钉不住就明说不可恢复并点名清掉了哪几个**。要防的是静默。
- **这一跳没成就把同步的 merge commit 撤掉**(`reset --keep`,会覆盖本地改动时失败而
  不是毁掉它们)。不撤的话用户分支上的东西会灌进之后每个席位的基线、把用户的活算进
  run 的产出、和 `userRewound` 打架。只在集成分支此刻正好还是我们造的那个提交时才动。

### 四、被挡住时:两条判据,一条就够,但外层是全称

`intoTrunk` 被「你的本地改动会被覆盖」挡住时,对**每一条挡路路径**问两个问题:

1. **归因**:它被某个席位点名写过吗(`escapes.owns`)。
2. **可证明无损**:工作区里的内容,和这次合并**将要写入**的内容,是不是一个字节不差。

第 2 条不需要知道是谁写的 —— 相同就意味着丢弃它**不损失任何东西**,合并马上会产出
一模一样的字节。它天然覆盖 Bash 那一类(devenv 重新生成出和分支上一样的 lock),
而且对用户自己的改动也安全。

**为什么必须有第 2 条**:硬闸默认开 ⇒ 每次越界都被拒 ⇒ 记录全是 `blocked` ⇒
`owns()` 恒假。两个特性在争同一个证据源 —— 闸只看得见「我们没让它写成」的那些,
而这里要的是「已经落了盘并挡住合并」的那些。**闸拦得越干净,归因这条路越空。**
只有第 1 条的话,park 在出厂配置下是死代码。

外层是**全称**:只要有一条既归因不到、又证明不了无损,就整个不动
(拒绝合并、如实报告、一个字节不碰)。少数服从多数在这里不成立 ——
混进去一条用户的改动,钉走它就是丢他的活。

动作也分两种:归因到席位的**钉成耐久 ref**(它们带着够不到任何分支的内容),
可证明无损的**直接清掉**(钉一份和分支上一样的字节只会给用户一条永远用不上的 ref)。

三个细节各自付过账:

- **挡路清单按 TAB 切**,不按标点猜。真 git 实测:这两条消息的文件清单每一行都以 `\t`
  开头,空格原样、UTF-8 不转义。按 `!includes(' ') && includes('.')` 猜会漏掉
  `Makefile`/`Dockerfile`/带空格的路径 —— 而漏摘的方向是危险的那个:`every()` 在被削过的
  集合上求值,剩下的恰好都是席位的 → 判真 → **把用户的 Makefile 一起钉走**。
- **pathspec 每条加 `:(literal)`**。这些是从 git 输出里原样摘的字面文件名,而 pathspec
  默认吃 wildmatch:`stash push -u -- 'a[1].txt'` 会连 `a1.txt` 一起收走。
  `[id].tsx` 在真实仓库里遍地都是。
- **钉走的范围 = 挡路的那几条**,不是整棵树。判据保护的是名单,动作也只能是名单。

**retry 撞了现场要收拾,而且 `left`/`restored` 要重算**:钉走脏文件之后真三方合并才跑
起来,它可能撞真冲突。不 abort 的话用户主检出里留着 `UU` 和写进文件的冲突标记,
而组装消息时沿用 park 之前那两个值,屏幕上会说**「已还原你的工作区」**、`conflicted: false`。
顺序也要紧:不先 abort,`stash apply` 会撞 `could not write index`。

**放回要按 ref**,不能裸 `stash pop`:`pinAndClear` 钉成耐久 ref 之后会把自己那条 stash
条目 drop 掉(`refs/stash` 是全仓库共享的),所以栈顶剩的是**用户自己**那条 ——
裸 pop 既放不回席位那份,又把用户一条无关的 stash 摊进工作区并删除。

### 五、说出来,而且要活过这块屏

- 运行中走 `RunningView.problems`。生产者 `pushNotice` 留**最新** 20 条,消费端就必须
  取**最新** 3 条(`slice(-3)`)—— 两端方向相反的话,攒够 3 条之后新告警永远进不了屏幕,
  只让「另有 N 条」的数字变大。事故当天的现象正是 40 分钟里积压 16→27。
  `runNotices` 排在 `redoProblems` **后面**(会动的那一栏靠后)。
- 报失败原因优先取 **stderr**:合并失败时 stdout 的第一行常常是 `Auto-merging x.txt`
  这种*成功*输出,拿它当原因念出来就是「没能同步(Auto-merging base.txt)」。
- 钉走的耐久 ref 要进**退出报告**。`refs/et/rescued/*` 全仓没有任何扫描器会再列出来
  (`sweepStashBackups` 扫的是另一个前缀,`scanStranded` 的 fsck 只看 unreachable),
  而运行中那块屏是滚动的 —— 不写进退出报告,run 一结束,用户取回**他自己那份内容**
  的唯一线索就永久消失。

## 为什么不是别的方案(这些判据是实测出来的,不要再走回去)

### 前后给主检出拍 `git status` 指纹 —— 它会**自己造成**要修的那个故障

- `git status --porcelain` **会写 `.git/index`**(刷 stat cache),因此抢 `index.lock`。
  20 席 × 每次派发两拍打在 gitRoot 上 → **merge 失败 38/40**。
  **检测手段自己复现了「集成分支前进、master 不动」。**
- 20 个诚实席位、零越界、500 对指纹 → **误报 52/500**。归因实验:1 个作弊席位越界 5 次
  → **15 个席位被点名,14 个是冤枉的,而作弊者从第 2 次起隐身**。
- porcelain 是**电平**不是**边沿**:已经脏的文件再被改写,前后输出逐字相同;
  席位写完 `git commit` 则完全隐身 —— 而那正是最致命的一条。
- 这正是 `verifySnapshot` 自己的注释(`pipeline.ts:2364-2374`)**明令禁止**的那一档。

工具输入是**边沿触发**的:越界 4 次记 4 条,而且天然带席位身份。

### 「连续 N 次就停」 —— 机制不成立

`noteSkip` 按整串消息去重,而消息里嵌着随批次变化的文件名 → **永远数不到 N**;
run 级内存计数器 `--resume` 归零(`trunkLanded` 的注释为同一个坑写过一遍)。

### 只报告、不动手 —— 缺的从来不是信息

对照实验:不钉的话 10 个节点完成 → 合上 0,20 个 → 合上 0,**永不自愈**。
git 在第一次失败的那一秒就把文件名放进了 `detail` 里。缺的是**让合并成功**。

### 「脏了就钉走」 —— 用户明确否决过

`stashGuard` 文件头逐字写着「默认关,由用户按一下打开」。所以要么归因到席位,
要么证明无损,二者都没有就一个字节不碰。

## 判据(缺一条就是没测)

源码文本断言只能钉「这一行在不在」,**钉不住条件被改坏**(实测:把
`if (box && !box.current.includes(...))` 改成 `if (box && false)`,字符串还在,全绿)。
所以凡是有行为的地方都抽成能真调的函数(`gitSpawnEnv`、`buildEscapeLine`、
`rememberEscapeRef`、`toolNameOf`、`resolveLinks`、`normalisePath`)。

接线闸门用**计数式 + 非零基线**:`expect(calls).toBe(3)` 那一句不能省 ——
锚点一变形两边同时归零,`"0/0" === "0/0"` 直接绿。

每一条判据都要有一条变异打得中它。这一批实测反复出现的失败模式:

- **探针测了空气** —— 场景根本没走到那段代码(注入失败的 abort 才能走到升级分支;
  往集成工作区放**已跟踪**的脏文件会让同步在更早一步被拒,`aborts` 恒为 0)。
- **判据要求一件做不到的事** —— 「重手之前必须钉住」,而冲突态下 git 拒绝 stash。
- **测试喂的形态和生产不一样** —— 测试喂字符串工具名,生产喂对象。
- **断言落在树上,而缺陷落在话上** —— `left` 重不重算只改变屏幕说什么和 `conflicted`
  标志,只查工作区状态是打不中的。

## 明写没修的

1. **Bash / MCP 不在硬闸内**。从命令行推断改了哪个文件不可靠,而下游要动用户的工作区 ——
   宁可归因不到,不可归因错。而且硬闸会把一次**会被记录**的 Edit 越界,系统性地推成
   一次**记录不到**的 Bash 越界(拒绝理由里原样带着主检出绝对路径)。
   「可证明无损」那条判据部分兜住了这一类。
2. **`cwd` 缺席即全关**。除共享工作树档,`acquirePlanBase` 失败那一路也会让带写工具的
   席位在主检出里干活,零记录零拦截。
3. **嵌套 `Agent(isolation:"worktree")`**:子 agent 的工作树建在 `<repoRoot>/.claude/worktrees/`,
   在 gitRoot 下、不在 `req.cwd` 下 → 每一次写都被拒,拒绝信息还告诉它一个错的工作区。
4. **Windows 上闸整层是空操作** —— 判据要求路径以 `/` 开头,而 Windows 上是 `C:\…` / `C:/…`。
5. **bun 的 `realpathSync.native` 词法处理 `..`** —— 实测 bun 1.3.14 对 `link/../a` 返回
   词法折叠的结果,而 node 和 coreutils 返回软链解开后的真实路径。出厂是
   `bun build --compile`,所以「先 realpath 再 normalise」这个常规修法在生产运行时上
   买不到东西。要真修得逐段解析。触发要软链和 `..` 同时出现。
6. **被 gitignore 的挡路文件** —— git 压根不为被忽略的文件挡合并,所以席位 `add -f` 的
   构建产物会**静默覆盖**用户主检出里的同名文件。这是 git 的行为,不是这一层能拦的。
7. **`Updating the following directories would lose untracked files in them:`** 是 TAB 清单,
   但 `overwriteBlocked` 的正则不认它 —— 席位在主检出里新建**目录**那一格不自愈。
